## 報告フォーマット
通常、負荷試験では作業記録として「負荷試験作業報告書」を作成します。報告書のフォーマットはプロジェクトごとに異なりますが、負荷試験のエビデンスとしてどのデータを添付するかは事前にすり合わせておく必要があります。

### 負荷試験のエビデンス
負荷試験の実施記録として考えられるエビデンスは主に以下のとおりです。

- サマリ（要約）ベースのエビデンス
  - 実施日時と負荷設定
  - 実施期間における主要な性能評価値
    - RPS（Requests Per Second）や総リクエスト数
    - 平均応答時間およびパーセンタイル応答時間（P90、P95 など）
    - エラー率 など
- 詳細ベースのエビデンス
  - 個別リクエストのスナップショット（必要に応じて抽出）
- 環境ベースのエビデンス
  - 負荷試験中に対象環境へ適切な負荷がかかっていたことを示すインフラモニタ指標（CPU/メモリ/I/O/ネットワーク等）
  - 対象インフラのサーバログ（必要な場合に限定）

JMeter を用いた試験ではサマリレポートの出力や個別リクエストの取得が可能です。クラウドベースの負荷試験ツールもサマリやグラフを提供し、結果の可視化に役立ちます。

### エビデンスの定義と運用上の注意
- 最低限、サマリベースのエビデンスは必ず添付する。グラフ等で視覚化すると理解しやすい。
- ツールごとに収集可能な指標が異なるため、事前に取得可能なデータ項目を列挙して合意しておく。
- 詳細ログ（個別リクエストやフルログ）はファイルサイズが大きくなることが多い。必要性と提供方法（抜粋基準、期間、オフラインでの受け渡し方法等）を事前に定める。
- サーバログや機密情報を含むログの提供は取り扱いに注意が必要。要求がある場合は範囲と提供方法（マスキング、抽出条件など）を合意しておくことを推奨する。

## AWS DLT のテストレポート
AWS Distributed Load Testing (DLT) のテストレポートについては公式ドキュメントを参照してください。
https://docs.aws.amazon.com/ja_jp/solutions/latest/distributed-load-testing-on-aws/test-results.html

> - Average response time - テストによって生成されたすべてのリクエストの平均応答時間 (秒)
> - Average latency - テストによって生成されたすべてのリクエストの平均レイテンシー (秒)
> - Average connection time - テストで生成されたすべてのリクエストについて、ホストへの接続にかかった平均時間 (秒)
> - Average bandwidth - テストで生成されたすべてのリクエストの平均帯域幅
> - Total count - リクエストの総数
> - Success count - 成功したリクエストの総数
> - Error count - エラーの総数
> - Requests per second - テストで生成されたすべてのリクエストの 1 秒あたりの平均リクエスト数
> - Percentile - テストの応答時間のパーセンタイル値。最大応答時間は 100%、最小応答時間は 0%。

シナリオが定義できたら、実際に負荷試験を実施します。
負荷試験のゴールは「事前に定めた性能目標を達成する事」になるわけですが、実際の負荷試験ではこのゴールに向けて段階できない試験実施を行い、性能課題の抽出を進めていく事になります

## 段階的な負荷試験の実施
負荷試験で目標性能を達成するためには、以下の2つのアクションを達成する必要があります。

- 応答時間の改善 : 負荷環境下でも目標の応答時間を出せるようにシステムが孕む性能課題を抽出して開発チームに改善を要求する。
- RPS　の達成　： 目標のRPSを達成するために、どの程度負荷をかければよいのかを計算する

応答時間は、低負荷から負荷試験を実施して段階的に性能評価を入れながら確認を進めていきます。いきなり高い負荷をかけて課題抽出するよりも、段階的に試験を実施して性能課題が表面化する負荷の規模感を明らかにすることで、性能課題の抽出だけでなく原因分析の効率化にもつながります。

目標RPSを達成するために必要な負荷の規模は、中規模程度の負荷試験実施結果から比例的に計算して導出することができます。
jMeter では jmx シナリオファイルを実行する際に、負荷のパラメータとして、conc のパラメータを設定できます。conc の値を増やせば増やすほど、対象システムへのリクエスト数すなわち負荷は高くなり、多くの RPSを結果として得ることができるようになる仕組みです。

このように、負荷試験の目標達成のためには、いきなり「低負荷」「中負荷」などの段階的な実施を経て最終的な本実施に繋げていくことが、全体の作業として効率的に進められます。本資料では、以下のとおり4つのステップに分けて負荷試験の実施を進めていきます。

- 低負荷試験の実施　：　負荷に依らない、根本的な性能課題の検出を行う
- 中負荷試験の実施　：　一定の負荷で表面化する、負荷起因の性能課題の検出を行う。また負荷環境下でのRPSを算出し、目標RP S到達に必要な負荷の規模感を予測する。
- こう負荷試験の実施　：　中負荷試験で算出した「目標達成に必要な負荷」を短時間実行し、算出した「必要な負荷」の妥当性確認と、「必要な負荷」基準で性能課題が表面化しないことを確認する。

## 低負荷試験の実施  

まずはconc1程度で負荷試験を実施します。

開発サイクル初期のシステムは、機能要件の充足をようやく終えたばかりで負荷性能が後回しになっているケースもよく見られます。

conc1の実行で十分な応答速度が出せないのであれば、もとより負荷性能で目標達成するできないため、優先的に改善を入れる必要があります。

note
低負荷試験の実施ては、jmeterを使わなくてもabコマンドを利用した簡便なテストで代替することも可能です。


## 中負荷試験の実施 

conc1の試験で適切な応答速度を達成したら、concを徐々に上げて応答速度の低下が見られないか確認して行きます。

中負荷試験では、およそ10-50程度のconcを用いて試験を行い、応答速度やエラー率への影響を確認します。
conc1で応答速度性能を達成していても、システムが負荷耐性を具備していない場合、軽微な負荷でも応答速度の低下やエラー応答の増加を確認することができます

## 大きな Conc の実現
手元のPCを利用してjMeterを実行する場合、PCの性能にもよりますが、Con c　100程度を閾に4っx系のエラーが発生したりRPSが伸びなくなる現象に直面することがあるでしょう。（gpt要確認）
これは、複数のリクエストを発行するコール処理がPCの処理限界に触れるために起こる現象で、CPU％が高い数値で張り付いているなどを根拠に限界の到達を確認することができます。

このようなケースでは複数台のPCを用意して分散した負荷試験の実施が必要になりますが、実際に2台以上のPCを用意して負荷試験を実施するのは、操作も面倒ですし、結果の集計も非常に憂鬱な作業になります。

AWS　DLTやBlazemeterはこうした分散負荷試験の環境を簡単に用意してくれるツールとなっており、大規模な負荷試験実施には欠かせない存在です。
AWS DLTやBlazemeter を利用する際には、単純にconcを大きく設定するのでなく、適切な数の分散環境を用意してconcを分割して設定することで分散環境の恩恵を受けながら負荷試験を進めることができます。

note
分散環境で一つの環境に設定可能なconcの上限は、環境のスペックやjmxファイルの種別によって異なります。各環境が余裕を持ってリクエストコールを実行できているかは、各環境のCPU指標を見ながら確認を進めていく

## 高負荷試験の実施 

中負荷試験で十分な応答速度を達成し本試験に必要なconも定義できたら、いよいよ本試験相当のテストを実施します。

高負荷試験のフェーズでは、本試験に必要なconcを用いて30min程度の短時間で負荷試験を実施します。

多くのケースでは、中負荷試験の結果をもとに比例的な計算でconcを増加させれば、そのまま目標rpsを達成できるでしょう。
が、システムの品質によっては、高負荷試験のタイミングで応答速度やrpsの低下、エラーの発生などが起こるため、サマリを確認しながら性能課題の抽出とシステムの改善を行います。

基本的には 30min 程度でも高負荷試験を耐えることができれば、メモリリークなど起きていない限り数時間程度の本試験に耐えうると判断できるはずです。

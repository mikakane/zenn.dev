本セクションでは、負荷試験の基本設計における「利用ツールの選定」について、説明します。

## ツールを利用した負荷試験
負荷試験は、サーバに一定の負荷がかかっている状態で、目標の性能を達成することができるかを確認する試験です。
負荷試験では「一定の負荷」を実現するために、対象のサーバに多数のリクエストを発行する必要があり、またその結果を計測し計測期間全体での集計を行う必要があります。
こういった作業を手作業で進めるのはあまりにも非現実的なため、通常は JMeter などの負荷試験用のツールを利用して試験を実施します。

**負荷試験で用いるツール例**
- JMeter
- AWS DLT(Distributed Load Testing)
- Blazemeter

## JMeter
JMeterは、負荷試験を行うためのオープンソースのテストツールで Apache から提供されています。ローカル PC で動作する GUI ベースのアプリケーションで、CLI 上での操作にも対応しています。

JMeter では、GUI を用いてテスト計画を作成することが可能となっています。作成したテスト計画は JMeter アプリケーション上で実行可能で、テスト実施後の結果集計や詳細ログ出力にも対応しています。

:::message
テスト計画には、対象のエンドポイントやリクエストのパラメータのほか、リクエストの実施期間や並列処理数などを定義することができます。
:::

JMeter で作成したテスト計画は、拡張子が `.jmx` のファイル形式で出力することができます。作成された jmx ファイルを JMeter に取り込むことで、誰でもテスト実行が可能となるため、チームでの作業も円滑に進めることができます。

JMeter は負荷試験ツールの第一選択肢として大きな地位を築いていますが、近年では後発の負荷試験ツールもいくつか開発が進められています。しかし、多くの後発ツールも jmx 形式のテストファイル読み込みに対応しているなど、JMeter の生成する jmx ファイルは JMeter 以外の領域でも広く用いられています。

このように JMeter は、「サーバに負荷をかける負荷試験実施ツール」と「jmx ファイルを作成するツール」との２つの側面を持っているといえます。

### JMeter の実行上限
JMeter は負荷試験実施ツールとしてエンドポイントへのリクエスト発行が可能で、エンドポイントに並列で大量のリクエストを送付することが可能です。ただし、JMeter は手許の PC で動作するプログラムであるため、PC のスペックによって実行可能な並列処理数に上限があります。
上限を超えたテスト実施は、不安定な結果を招き、リクエスト応答に多量のエラー結果が混ざることになります。

:::message
並列処理の上限は、様々な要因によって決まるため、一意にいくつまでが安定ということが言えません。
主に「手許PCの性能(CPU/RAM)」「jmxシナリオの複雑さ」「ネットワーク環境」などが並列処理数に影響します。
:::

:::message
通常 100 程度の並列処理は問題なく安定稼働させることが可能です。
500 を超える並列処理が必要な場合、AWS DLT などの分散実行環境を検討する必要があります。
:::

高い性能水準が要求される負荷試験では、手許の JMeter 実行では対応しきれないため、AWS DLT などの分散実行環境を検討する必要があります。

## AWS DLT (Distributed Load Testing)
AWS 製の負荷試験ツールでです。VPC 内に ECS 環境を構築してクラウドベースの負荷試験実施環境を構築することができます。
https://aws.amazon.com/solutions/implementations/distributed-load-testing-on-aws/

テストのシナリオには jmx ファイルが利用可能となっており、JMeter で作成したテストファイルを投入してクラウド環境上で負荷試験を実施することができます。

DLT は必要に応じて複数の ECS を構築し、より多くの並列処理を可能としている分散実行環境となっています。
CloudFomation ベースのテンプレートが公開されているため、AWS に関する知見が少ない人でも簡単に構築でき、かつ Build & Destory を簡単に進めることができます。

AWS DLT を利用した際のコストについては、以下公式のドキュメントにまとめられています。
https://docs.aws.amazon.com/ja_jp/solutions/latest/distributed-load-testing-on-aws/cost.html

DLT の環境はサーバレスな構成をベースにしており、ほとんどのコストは「使った分だけ」で抑えられるように設計されています。

## Blazemeter 
Blazemeter もクラウドベースの負荷試験ツールです。AWS の DLT と違ってインフラを自分で構築する必要がないため、SaaS サービスとして利用できるのが特徴です。
https://www.blazemeter.com/

Blazemeter も テストのシナリオに jmx ファイルを利用することができ、JMeter で作成したテストファイルを投入してクラウド環境上で負荷試験を実施することができます。

負荷試験の分散実行にも対応しており、異なるリージョンから複数台の環境で柔軟にリクエストを発行することが可能です。
結果のフォーマットが DLT よりも詳細でわかりやすい、といった特徴もあります。

Blazemeter の料金は以下のページから確認できます。
https://www.blazemeter.com/pricing

Blazemeter ではテスト実施に係るクレジットを VUH という単位でカウントしており、Proプランでは 80,000 VUH/year が利用可能です。
仮想ユーザー1人が1時間テストを実行することを「1 VUH」としてカウントするため、例えば、100ユーザの並列処理で1時間テストを実行すると 100 VUHが消費されます。

## ツールの選定基準

ツール選定は、まず分散環境が必要かどうかを基準に考える必要があります。

100 の並列処理を基準に考えた場合、例えば 0.8sec で応答するエンドポイントは、125 rps を実現することができます。1.5sec で応答するエンドポイントなら、66rps です。

要求される RPS の度合いによって、100を超える並列処理が必要になりそうな場合は、分散環境の手配を前提に設計を進めるのがよいでしょう。

負荷試験の分散環境構築では、AWS DLT が一般的によく用いられる方式ですが、AWS の知見が乏しい場合などは、Blazemeter などの SaaS ソリューションを選定することも選択肢の一つとなります。

いずれもコストがかかるツールになるため、コスト負担の方式や費用の概算などを添えて、クライアントと事前に握っておく必要があります。

## 制約の説明

ここまでツールを用いた負荷試験について説明してきましたが、負荷試験ツールはあくまで擬似的に負荷状況をつくりだすツールに過ぎず、実際の人間が行うリクエストとはいくつかの乖離があります。

- ツールが発行するリクエストは、あらかじめ決められた一定のパラメータを繰り返し断続的に実施するもので、リクエストに関するクライアント環境もテスト実施環境で固定されたものとなる。
    - 実際のリクエストは、パラメータが多様に変化するため、試験で予期しないパラメータにより想定外の負荷が発生する可能性がある
    - 実際のリクエストは、複数のエンドポイントに対して五月雨にリクエストが送られるため、リクエストの順序やその他の条件等で想定外の負荷が発生する可能性がある
    - 

負荷試験で負荷試験ツールを利用することは、ごく一般的なアクションですが、ツールを利用することで生じる実際のユーザリクエストとの差異については事前に説明が必要で、クライアントの納得を得たうえで進めていく必要があります。


- 負荷試験では、JMeter
